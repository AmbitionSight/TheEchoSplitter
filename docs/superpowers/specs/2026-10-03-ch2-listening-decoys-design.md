# 第二关「听声点 + 干扰音素」设计稿

> 目的：把第一关的听觉探索层还给第二关，并让拼词重新有"听辨"成分。**只改第二关**（裂谷 `chapter2` + 崖壁 `chapter2b`），第三关不动。

## 背景（为什么）

第二关起，第一关最"游戏"的回声物（碰一下→念声音→符文亮）归零，且掉落恰好等于所需音素——拼词没有选择，只剩搬运。本稿补回探索与听辨，但**刻意不照抄第一关**。

## 一、听声点（回声层）

与第一关的差异：

| | 第一关 | 第二关（本稿） |
|---|---|---|
| 触发 | 按 E 点一个物件 | 走近**按 E**；听声点是场景里**已有的实体物件**（火把/断崖/墙/窗），走近显示 E 提示 |
| 内容 | 孤立单词（Water/Fire…） | 同样清晰易辨的单词，但**不追求近音对照**（用户要求"音不要太难"） |
| 状态 | 静止 | **一处随进度变化**：裂口边缘在解锁跳跃前回 "Fall."，能过坑后回 "Free."（前进途中即可听到） |

- 数据：`content.listening = [{ id, x, y, r, echo:[ipa...], say:"Word.", after?:{echo,say}, auto?:true }]`；`x,y` 对准对应场景物件。
- 事件机：新增 `case 'LISTEN'`（`gameEvent(g,'LISTEN',id)`）→ `[{t:'sfx'},{t:'echo', ipas, say}]`；`after` 变体在解锁跳跃后生效。纯逻辑，Node 可测。
- kit：**E 目标**的听声点由 `findE` 认它、`onE` 触发 `LISTEN`（复用 `drawEHint` 的 E 提示）；`auto:true` 的（火把）改为 **tick 里走近自动响**、不占 E。世界层在物件上叠一层微光（`drawListenSpots`）。
- 复用现成 `echo` 指令与回声条/符文机制；`createGame` 补 `heard` 字段（第一关有、第二三关原缺），使回声点亮析声录符文。

## 二、干扰音素

- 掉落 = 本词所需音素 **+ 2 个**从 `profile.everPicked` 挑的、**明显不同**的已学音（用户要求易区分，不用近音）。
- 实现：`content.words[word].decoys = [ipa...]`；`planDropStones` 把 decoys 一并掉落（无该字段则行为不变，向后兼容）。
- 效果：玩家要从熟音堆里听辨出本词的组成，而不是"掉什么捡什么"。

## 不做（本稿范围外）

- 第三关（暗河）的回声/干扰。
- 最小对立对（易混音对照）——太难，与"音不要太难"冲突。
- 多候选词（诱饵词）——内容成本高、有挫败风险，留作后续。

## 验收

- `npm test` 全绿（新增：LISTEN 指令、decoys 掉落、内容结构）。
- 真机：走进听声点响起并点亮符文；拼词时需从多余音素中挑出正确的；裂口回声跨越前后不同。
