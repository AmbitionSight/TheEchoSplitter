# 第三关·岸边场景 洞穴化重设计

> 2026-10-03。范围：**只做岸边一间房**（裂隙房、深水房留待后续两轮，各自单独出稿）。
> 上位文档：`DESIGN.md`《同一块石头》、`docs/superpowers/specs/2026-10-03-ch1-background-redesign.md`（第一关《石匠像素》）。
> 本稿只动画面层，不动事件机、不动玩法几何。

## 缘起

对第三关与第一关的画面精细度做过一次系统对比（八维度、逐条核验），结论：差距不是笔触粗细，而是**整层系统缺失**——第三关的墙地是「一条纵向渐变 + 18 条写死发丝线」，且每帧重画；同族的第二关在用的 `drawMossyWall` / `drawFloorSide` / `drawTorchSide`，第三关一个都没调用。

本稿做三件事：把岸边墙地换成**洞穴版程序化生成 + 预烘焙**；把河流从静态曲线换成**流动水**；把岸边几件物件（裂隙口、木筏、巨石、原木）补上结构细节与落地影。

## 范围

| 场景 | 本轮 | 说明 |
|---|---|---|
| **岸边**（`room === 'bank'`） | ✅ 本稿 | 出生点、合成台、裂隙口、水边逐根放原木、组筏、登筏 |
| 裂隙（`room === 'crevice'`） | ⬜ 下一轮 | 取原木音素石、回程口 |
| 深水（`room === 'deep'`） | ⬜ 下一轮 | 漂流、停摆、岩画、壁龛、拼 pole、撑篙 |

**木筏 ≠ 木篙。** 木筏在岸边就组装出来并停在岸边（`parked`）；木篙是深水房才拼出来的。因此本轮木筏**无木篙、无撑篙动画**，`riding` / `poling` 状态与撑篙演出随深水轮一起做。

同理，两处 `fillText` 文字占位（`render.js:62` 的 `'◼  ◼  ◼'` 在裂隙房、`:114` 的 `'石壁上的撑篙图'` 在深水房）不在岸边，留到各自那轮清除。

## 决策

### 1 · 岩壁与地面：只搬技法，材质换岩壁

沿用第一关的**全套技法与数值**，但「块」是不规则天然岩面，不是成排错缝的矩形砖。

| 手法 | 数值（与 ch1 一致，保证同一门语言） |
|---|---|
| 逐块明度扰动 | `shade(base, t - 1)`，`t = 0.9 ± 0.2` |
| 上/左受光边 | `+0.16` |
| 下/右沉影边 | `-0.22` |
| 苔藓 | 自岩面下缘向上，2×2 拜耳有序抖动生长 |
| 洞顶沉暗渐变 / 墙脚落地阴影 | 同 ch1 的 `WALL_SEAM` 做法 |

**规划方式改为「抖动网格 + 多边形岩面」**：粗网格（120–220px）打底，种子 RNG 抖动网格顶点（±cell×0.18），相邻面**共享顶点**以保证无缝隙；每面画成边界弯曲的不规则多边形。

**洞穴专属母题**（「地下洞穴感」的来源）：钟乳石（洞顶垂下）、石笋（地面立起，须避开玩家行走区）、顺壁而下的湿痕水渍、横向岩层走向线。

**岸边这一间的参数**：靠水，湿度调高，苔藓更盛。

**图集失败不影响本层**——岩壁生成器是纯矢量，比第一关的兜底更稳。

### 2 · 光照：只补接触阴影与环境遮蔽，无主动光源

本轮**不建光源系统**（无光池、无暗海挖孔、无火焰光晕、无色罩）。

没有光源就没有方向，因此阴影做成**环境遮蔽式**而非定向投影：

- `contactShadow(x, cx, cy, w)`：每个落地物件脚下一枚柔和椭圆（沿用 ch1 的 `rgba(0,0,0,.25)` 起手）
- 墙地交界处压暗
- 岩缝、凹槽、钟乳石根部加局部压暗

覆盖：合成台（共享件已有，沿用）、裂隙口、原木、木筏、系泊块、巨石。

> **为将来留口**：岩壁生成器输出**中性底**（不含光方向假设），日后加光源时不必重做材质。

### 3 · 水面：只重画水，镜头不动

不新增滚动/视差/镜头跟随机制——木筏平移时背景保持静止。

`drawWater(x, w, t)` 三层：

1. **底**：横向深浅渐变（近岸浅、河心深）
2. **中**：现有 9 条静态二次曲线改为**受 `t` 与 `x` 调制的流动波**——横向相位滚动 + 纵向正弦起伏，多层不同速率
3. **表**：岸线泡沫、水面高光碎点（种子固定点阵，随时间闪烁）、木筏周围水花环

另加**倒影**：洞顶与裂隙口在水面拉出柔和的竖向拖影。水是本关唯一「亮」的元素，承担了原光照层的一部分职责——但它是**材质处理**（高光/反射），不是光源，不违反「本轮不建光源系统」的边界。

`drawRoom(w, x)` 的签名不变：动画所需的 `t` 已经在 `w.view.t` 上，无需新增参数。

### 4 · 裂隙口：门 → 人高裂缝

岸边 `geo.bank.doorX = 650` 处的石拱门（现 `render.js:42-44` 的两个梯形）删除，改为 `drawCrack(x, cx, groundY, seed)`：

- 约 170px 高，**底宽（半宽 ~35px）顶窄（半宽 ~12px）**
- 锯齿边缘由种子生成，左右两缘各一串折点
- 内部近黑（`#0a0d12` 族）+ 竖向纵深渐变
- 唇口受光边 + 崩口碎石
- 与裂隙房那道贯穿全屏的锯齿大裂缝**同源**：`drawCrack` 按「尺寸 + seed」参数化，岸边本轮先用；裂隙房那轮把现有内联绘制（`render.js:56-64`）也换成同一个函数的不同参数，届时岸边这道缝与裂隙房那道大缝是同一道缝的两段

**交互完全不动**：`kit.js` 的 `creviceDoor` 目标仍是 `x = geo.bank.doorX`、`y = geo.bank.groundY`、`r = 110`。手感与测试都不变。

### 5 · 木筏：结构写实（本轮只做停泊态）

现 `drawRaft`（`render.js:126-134`）是 5 根圆角条 + 2 笔金色交叉线。改为：

- **结构**：5 根以上木板（木纹折线 + 左端年轮同心椭圆）、2 根横梁、绳索缠绕与绳结
- **停泊态** `parked`：吃水浅、微幅慢晃

函数签名预留状态位（`w.raft.state`），本轮岸边恒为 `parked`；`riding` / `poling` 与撑篙演出随深水轮实现。

### 6 · 石墩 → 洞穴巨石，并向左挪开

现 `render.js:39` 在 `(565, groundY-100, 150, 90)` 画一个灰色圆角方块，无命名、无功能、无剧情指涉，且与裂隙口（595–705）在 x 上重叠 110px、填充色几乎相同（`#67727d` vs `#6b7078`），糊成一团灰块。

改为：用新岩面材质画成一块真正的洞穴巨石（不规则多边形 + 崩口 + 落地影），**左缘 470、右缘 560、宽约 90px**，位于合成台（精灵范围 284–436）与裂隙口（595–705）之间，两侧各留 ~34px 空隙，给裂隙口腾出空间。巨石无碰撞、无交互，纯陈设。

### 7 · 原木

水边逐根放下的三根（现 `drawLog`，`render.js:117-124`：圆角条 + 端面椭圆）跟着木筏一起加结构细节，保持同族语言。

## 工程边界

**新建**

- `public/js/ch3/cave.js` —— **纯函数**：岩面/钟乳石/苔藓场规划器。无 `document`、无 canvas，Node 可直接 import。
- `test/ch3-cave.test.js`

**修改**

- `public/js/ch3/render.js` —— 房间背景改读烘焙层；裂隙门 → `drawCrack`；水面 → `drawWater`；木筏 → 结构版；新增巨石；物件补落地影
- `public/js/ch3/kit.js` —— `makeWorld` 建场景对象；boot 时烘焙岸边静态层；`draw()` 改为先 `drawScene` 再画动态物件
- `content/chapter3.json` —— 预计不动（巨石坐标、裂隙口坐标都在渲染常量或已有 `geometry` 里）；若需新增岩面种子等参数，加到渲染常量而非 content

**不动**

- `public/js/ch1/*`（第一关已完工且有测试锁定）
- `public/js/sideview.js`、`chapter.js`、`workbench.js`、`hotbar.js`
- `public/js/ch3/event.js`（事件机零改动）
- 裂隙房、深水房的绘制代码

**分层归属**：沿用第一关的分法——**规划器纯函数进 `cave.js`**（Node 可测），**上色/烘焙留在 `render.js`**（浏览器专属）。这与 CLAUDE.md 的「browser-only global access 必须关在函数或浏览器入口里」一致。

**烘焙策略**：`initScene` 在 boot 时把岸边静态层烘成一张 1280×720 离屏图，运行期每帧只 `drawImage` 一次。`drawRoom` 优先使用烘焙层，**没有烘焙层的房间回退到现有代码路径**——这样后两轮可以逐房迁移，不必一次改完。裂隙房与深水房本轮继续走旧路径。

## 测试与验收

**新增 `test/ch3-cave.test.js`**

- 确定性：同种子产出完全相同的计划；不同种子产出不同计划
- 几何不变式：所有岩面顶点落在 `[0,W]×[0,H]` 内；相邻面共享顶点、**无缝隙无重叠**
- 苔藓：只出现在 `wet > 0` 的岩面上，且只自下缘向上生长
- 湿度分区：岸边参数下靠水侧苔藓密度高于内侧

**回归**

- `test/ch3.test.js`、`test/ch3-event.test.js`：事件机未动，应全绿
- `ch1` / `ch2` 测试全绿即证明未碰坏跨章共享件
- 现有 155 个测试不得减少

**浏览器验收**（`npm start` 后截图对比）

- `?autostart=1` —— 岸边初始态（含裂隙口、巨石、水面）
- `?autostart=1&beat=assembled` —— 组筏完成态（含木筏结构、三根原木）
- 判据：岩壁可辨逐块明暗与苔藓；裂隙口一眼能读作「可以进去的地方」；水面有流动与高光；物件不再悬浮；巨石与裂隙口不再糊在一起

**不达标即回退**：若岩壁在无光源前提下细节仍读不出来，回到本稿讨论「是否提前引入主光源」，而不是继续加笔触。
