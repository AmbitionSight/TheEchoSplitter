# 析声者（The Echo Splitter）· 第一章 设计规格

> 注：本项目原名「回响之石 / The Echo Stone」，2026-10-03 更名为析声者。文中旧名均指同一项目。

> 日期：2026-10-01 ｜ 状态：已经用户逐节确认
> 本文档在用户原始规格基础上，整合六轮设计问答的全部决策，为唯一权威实施依据。

---

## 0. 一句话概括

在一间中世纪石室里，碰一碰物件，词的音素会像掉落物一样掉出来；把它们捡进口袋，在 Minecraft 式工具栏里拼成「词具」，用声音点亮黑暗、浇活枯苗、打开尽头的石门。

**教学哲学**：第一性原理学英语——语言直接对应画面与声音，玩家像婴儿一样泡在声音里，自己发现音素。音素不是教的，是发现的。

## 1. 教学铁律（不可违反）

1. 目标语言（英语）只以「声音 + 情境」出现：NPC 只出声不出字，**禁止显示英语句子字幕**。
2. **禁止任何形式的翻译**：不用中文解释词义；词义只能通过画面、手势、动作、戏剧事件传达。
3. 系统永远不主动教「这是音素 /æ/」；只在玩家的行为（拾取、拼对）之后做确认与庆祝。
4. 反馈只有自然反应：NPC 点头/摇头/歪头/放慢重复，世界变化（灯亮、门开、花开）。**没有红叉、没有评分、没有「错误」字样。**
5. 中文仅用于系统级元提示（操作说明、当前目标），永不用于解释英语含义。
6. 不使用麦克风输入；「开口说」用**拼词组合**代替（更稳、可离线）。
7. 音素石上的 IPA 字符是「声音的记号」，不属于英文拼写，允许显示；英文拼写全章只在 OPEN 揭示卡出现一次（那是刻意的唯一教学时刻：文字，是冻住的声音）。
8. 禁止 emoji：全部图标为手绘 Canvas 矢量。

## 3. 核心循环与流程节拍

**一套规则贯穿六个词：碰 → 拾 → 拼 → 用。** 全游戏只有这一种交互心智模型。

### 3.1 节拍表

| # | 节拍 ID | 内容 |
|---|---|---|
| 1 | `title` | 标题页：毛玻璃 + 发光符文 ᚫ 浮动 + 蓝色开始按钮 |
| 2 | `prologue` | 序章卡三句：「你的语言被偷走了。/ 你走进一间陌生的石室，只有一个声音在等你。/ 碰一碰这里的东西——声音会掉出来。」 |
| 3 | `hello-listen` | 大叔招手 "Hello! Hello!"——只有声音与手势，无任何文字 |
| 4 | `hello-meet` | 玩家走过去点他 → 点头笑 "Hello! Yes, you!" → hello 入书 + **掉 h·ə·l·əʊ 四石** |
| 5 | `explore-left` | 自由探索亮区：井→w·ɔː·t·ə ｜ 火盆→f·aɪ·ə ｜ 灯柱→l·aɪ·t（台词均由大叔喊出） |
| 6 | `first-stone` | 首颗石入手 → **工具栏从底部滑入** + 提示「声音石进了口袋——点右下角的符文，试着把它们拼在一起」 |
| 7 | `craft` | 展开槽位行 → 乱试拖石 → 凑成 light → 共鸣发光 + 童声朗读 "Light." → **提灯词具入栏** |
| 8 | `use-light` | 拖提灯到灯柱拉闸 → 咔哒 → **1.2s 光潮涌向右半** → 门、帽架、两支未点燃火炬从剪影淡入 |
| 9 | `explore-right` | 帽架→h·æ·t → 拼出草帽 → 拖到自己头上 → **戴上**（橘猫竖尾好奇） |
| 10 | 支线（可选，随时） | water→浇活井边枯苗（开花粒子）｜ fire→点燃右墙双火炬 ｜ hello→大叔回礼大笑招手 |
| 11 | `door-awake` | 5 词集齐（hello+water+fire+light+hat 入书）→ 门符文青色脉动 → 走近/点击 → 低语 "Open… open… open the door!" + **四颗门语之石从符文处掉落** |
| 12 | `echo` | 捡起 əʊ·p·ə·n → 拼 open → 拱门词具 → 拖到门上 → 四石绕拱依次咏亮 → 石门低缓念 "Open." → **童声爆发 "Open!"** → 揭示卡 `əʊ · p · ə · n → OPEN`（「你用声音打开了门 / 文字，是冻住的声音」）→ 门开金光 → 结算卡 |

**第 11 节是题眼**：门「说」出自己的名字、声音结晶成石掉给你——你捡起它的声音、重组、再说回给它。这就是旧名「回响之石」的含义（拆开声音，再拼回说给它听——如今它叫析声者），同时解决「开门前哪来的 open 石」的因果闭环（先闻后仿，而非原稿的门开后掉石）。

### 3.2 门控（gate）规则

- `hatstand` 的交互 `requires:"lit"`：黑暗中不可点击、不可走位交互。
- `door-awake` 条件：书中有 hello+water+fire+light+hat 共 5 词。
- open 的音素石只来自门醒掉落（p 全章仅此一处来源）。
- **词入书时机**：hello=首次点击大叔；其余=**合成成功时**（拾到石头不解锁词条——拼出来才算「学会」）。故「碰完一切但从不合成」时门不醒，由大叔卡关提示引导（§3.3）。
- 其余全部自由：孩子可以在碰灯柱之前就用 hello+water+fire 的重复石拼出 light（这是聪明的奖励，不是 bug）。
- 无任何死局：已验证任意合成顺序下每个词仍可自给自足（重复音素 h/t/ə/l/aɪ/əʊ 跨词共享，但每词自身掉落必含全部所需）。

### 3.3 引导系统（全部为自然反应，零教学）

- 提示条随节拍更新（中文元提示，见 §10 hints）。
- 大叔卡关提示：45s 无进展时，有未收集词 → 低声念 npcTease（配指点手势）；石头已够却未合成 → 指指工具栏放慢念一个可拼词。
- 合成槽**渐进共鸣**：拖对某词的开头第一颗，槽缘微亮；对两颗更亮（无声脚手架，类似 MC 配方书暗示）。
- 灯柱拉闸开局可点：咔哒咔哒空响、灯不亮（暗示缺了什么）。
- 门醒后符文青色脉动吸引。

## 4. 词具系统（碰→拾→拼→用的「用」）

| 词 | 音素（石数） | 词具图标 | 使用目标 | 效果（一次性完整版） | 重复使用 |
|---|---|---|---|---|---|
| hello | h·ə·l·əʊ（4） | 气泡 | 大叔 | 大笑招手 "Hello! Hello!" | 再念一遍+挥手 |
| water | w·ɔː·t·ə（4） | 水滴 | 井边枯苗 | 浇水→开花粒子+大叔鼓掌 | 苗微微点头+再念 |
| fire | f·aɪ·ə（3） | 火焰 | 右墙双火炬 | 炭火式点燃+暖光晕扩散 | 火苗窜一下+再念 |
| hat | h·æ·t（3） | 草帽 | 玩家自己 | **戴上草帽**（外观变化，橘猫竖尾） | 整理帽檐+再念 |
| light | l·aɪ·t（3） | 提灯 | 灯柱拉闸 | 灯头燃起→1.2s 光潮→右半亮 | 灯微微一亮+再念 |
| open | əʊ·p·ə·n（4） | 拱门 | 石门 | 四石绕拱咏亮→"Open."→童声"Open!"→门开金光 | 门后风声+再念 |

- **词具不消耗**：永久保留。每个目标只完整响应一次（`once:true`）；重复使用 = 童声再念 + 目标轻微反应。理由：语言学习鼓励重复说。
- **拖错词具**（如把 water 拖上门）：目标纹丝不动 + 低沉咕哝一声（自然反应，无红叉、无弹窗）。

## 5. 底部工具栏与合成（HUD 核心）

```
展开态（点卢文钮 ⌂ 切换）：
┌────────────────────────────┐
│   ◈   ◈   ◈   ◈    ← 4 个合成槽位行        │
├────────────────────────────┤
│ [l·1][aɪ·1][t·1][h·1] [💡] [⌂] │
│   音素石堆(计数) · 词具 · 卢文钮          │
└────────────────────────────┘
```

- **实现层**：DOM + CSS（iOS 毛玻璃），不占画布帧。
- **音素石格**：同音素堆叠 + 计数角标；元音石黄、辅音石蓝，上书 IPA 字。**点击任何石头 = 播放其载词发音**（童声）。
- **合成规则**：4 固定槽；从栏内拖石入槽；**从首槽起连续排列的序列命中某词 → 共鸣**：四槽青光波 + 童声朗读全词 + 词具飞入栏 + 消耗对应石头。乱放/缺石/错序 → 永不亮、永不报错、可随时拖回。
- **跨层拖拽**（词具→场景）：pointerdown 在词具上 → 全局拖拽幽灵（`G.iconURL` dataURL）→ pointermove 跟踪 → pointerup 命中检测：坐标经 DPR/等比缩放换算到逻辑 1280×720，与场景目标包围盒/圆形半径求交 → 命中触发使用，未命中回弹动画。Pointer Events 统一鼠标+触摸；pointercancel 自动回弹。
- **合成槽内拖拽**：纯 DOM 内部重排，同一套 pointer 逻辑。

- 墙面：石砖 + 拱形月窗（月亮星星）+ 左右火把 + 一排装饰符文刻痕 + 墙脚阴影。
- 地板：64px 棋盘格双色石砖 + 石纹裂缝 + 中央圆形红地毯（金边双环）。
- 灯柱在左中分界，悬臂吊灯横跨中线；开局死火，拉闸开关可点（空响）。

### 6.2 黑暗与点亮

- 右半开局约 8% 亮度**剪影**（门/帽架/火炬轮廓隐约可见，制造「那边有东西」的欲望），黑暗区目标不可交互、不可走位。
- 实现：预渲染暗角贴图（径向渐变，中心=灯柱灯头）两档透明度切换；点亮时 1.2s 缓动 0.92→0，同时右半物件从剪影淡入 + 上扬音效 + 浮尘粒子被光照亮。
- 60fps：暗角为预渲染贴图，不做每帧渐变计算。

### 6.3 角色与演出

- **大叔（NPC）**：男声。开场招手；被点时确认/庆祝；卡关时低声提示；词具回礼时大笑。口型由 onboundary/定时脉冲驱动。
- **玩家**：蓝兜帽小孩，童声（女声偏高）——**只用于读石头载词、朗读合成词、喊 "Open!"**（拼词即开口说）。WASD/方向键行走（腿部交替、朝向翻转、影子、行走 bob）；点击目标自动走位，手动按键打断。
- **橘猫**：地毯左侧，纯氛围；点击喵一声+竖耳；词具成功使用时好奇反应（竖尾/抬头）。
- **石门**：右墙拱形木门（石拱框+铁箍+刻 ᛟ）；沉睡→符文青色脉动→咏亮→绕左轴收窄（0.94 渐变）→门后金色暖光+光尘上飘。

## 8. 词语之书（独立全屏页，B 键开合，Esc 关闭）

- iOS 分段页签：**词语 / 声音符文（n/48 角标）**。
- **词语卡**：手绘图标 + 风格化波形（按音素时长生成；已收集音素段高亮）+ IPA 行（如 `h · ə · l · əʊ`）+ 蓝色「听见」按钮。
- **声音符文页**：48 槽按课本三组分区；被拾取过的音素点亮符文卡（大符文发光呼吸 + IPA + 来源词图标 + 点击朗读载词与来源词）；未解锁显示暗色「沉睡的声音」槽；结尾卡「还有 N 个声音沉睡在更深的房间里……」。
- 注：符文点亮按「曾拾取过该音素」计，**不因合成消耗而熄灭**（学会的声音永不丢失）。

## 9. 美术风格（两种风格并存，不可混淆）

### A. 游戏画面：元气骑士（Soul Knight）式 2D 俯视卡通
- 厚描边（4–6px `#20242f`）+ 扁平色 + 一条暗部带，Q 版大头比例。
- 黄昏暖光氛围：火把/火盆/提灯径向光晕、缓慢浮尘粒子、边缘暗角。

### B. UI：苹果科技风（iOS 设计语言）
- 毛玻璃：`backdrop-filter: blur(28px) saturate(160%)`、`rgba(28,28,32,.72)` 底、1px `rgba(255,255,255,.14)` 描边、28px 大圆角、大而软投影。
- 主按钮系统蓝 `#0A84FF` 胶囊；次级白玻璃 ghost；文字 `#F5F5F7`/次级 `#A1A1A6`。
- 字体栈：`-apple-system, "SF Pro Display", system-ui, "Segoe UI Variable", "Segoe UI", "PingFang SC", "Microsoft YaHei UI"`。
- 组件：分段控制器、底部浮动胶囊提示条、顶部通知式 toast、发光符文卡、MC 式工具栏（iOS 质感化）。

### C. 图标：禁止 emoji
- `G.drawIcon(ctx, type, cx, cy, size)` 场内绘制 + `G.iconURL(type)` 生成 dataURL 供 DOM。
- 图标集：气泡=hello、水滴=water、火焰=fire、草帽=hat、提灯=light、拱门=open、菱形宝石=声音石袋。
- 卢文用矢量折线绘制（48 音素 strokes 归一化表）。

## 11. 技术架构

### 11.1 总体
- **Node.js 零依赖服务器**（内置 http 模块）：静态托管 `public/` + `GET /api/chapter1` 返回上述 JSON。`node server.js` 一条命令启动，端口 3000。
- 前端原生 JS + Canvas 2D，无框架、无构建、无外部资源，完全离线可玩。
- 逻辑分辨率 1280×720，DPR 自适应，等比缩放居中。
- 内容与代码分离：全部文案/词表/时长/载词/提示在 `content/chapter1.json`，客户端 fetch。

### 11.2 文件结构

### 11.3 语音（speechSynthesis）
- 角色音色：大叔=男声（pitch 0.9, rate 0.95）；童声=女声偏高（pitch 1.25, rate 1.0）；石门低语=男声低沉慢速（pitch 0.7, rate 0.8）。
- **启动时音色探测+打分**：枚举 `getVoices()`，按 `lang` 前缀 en-* 优先、性别关键字匹配角色排序；Chrome 需用户手势后才能发声（开始按钮即手势）。
- `onboundary`/定时脉冲驱动 NPC 口型；**兜底**：无 speechSynthesis、无 onend、或超时（按 380ms/词 ÷ rate 估算）即继续流程，绝不卡死。

### 11.4 音效（WebAudio 振荡器合成）
点击咔哒、拾取风铃、合成共鸣琶音、渐进共鸣微音、词具入栏滑音、点灯上扬扫频、火炬点燃、浇水/花开、戴帽噗、大叔笑、拉闸空响（咔哒咔哒）、门低语低通垫音、门咕哝低音、开门吱呀+金光合唱垫、猫叫、火把噼啪、失败闷响（仅用于拖错词具的咕哝，不用于任何「判错」）。

### 11.5 物理与移动
- 音素石掉落：向上抛出 → 重力下落 → 落地弹跳（能量×0.45 衰减）→ 静止后上下浮动 + 描边闪烁。
- 磁吸拾取：玩家半径 46px 内 → 石块加速飞向玩家 → 计数+1、风铃音效、袋子脉冲、符文点亮。
- 行走：房间边界 + 圆形障碍碰撞（井/火盆/帽架/灯柱/大叔各配半径）；按键优先并取消自动走位；点击交互距离 170px，超出先走位。

### 11.6 性能预算（60fps）
- 静态层一次性预渲染离屏画布：地板/墙面/地毯/左半静态道具。
- 动态层只画：火焰、光晕、门、暗区剪影/淡入道具、角色、掉落物、粒子、黑暗遮罩贴图（两档透明度缓动）。
- 工具栏/词语之书/面板全部 DOM，不占画布帧。

### 11.7 调试
- URL `?autostart=1`：自动开始 + 跳过序章点击，直达 `explore-left`。
- 控制台 `G.jump(beat)`：`title / prologue / hello-listen / hello-meet / explore-left / lit-right / door-awake / door-open / summary`。
- `window.__errors` 收集运行时错误。

## 12. 错误处理与边界

| 场景 | 处理 |
|---|---|
| 无 speechSynthesis / 无英文音色 / onend 不触发 | 估时兜底（380ms/词 ÷ rate），流程照走，绝不卡死 |
| 拖拽中 pointercancel / 拖出窗口 | 幽灵回收，石头/词具回弹原位 |
| DPR/窗口缩放 | 拖拽坐标统一经 canvas getBoundingClientRect 换算到逻辑坐标 |
| 任意合成顺序 | 已验证无死局（§3.2） |
| 重复使用词具 | 目标只完整响应一次，之后轻反应（§4） |
| fetch content 失败 | 内置最小内联副本兜底（与 JSON 同源），保证可玩 |
